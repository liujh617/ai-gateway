# v1.3.0: Content Safety Detection

## Overview

Add local keyword-based content safety detection for AI gateway audit logs. **Core principle: Data Sovereignty** - all detection happens locally, no external API calls.

## Features

### Content Safety Detection

- ✅ **Politics Detection**: Political figures, government agencies, political terms
- ✅ **Pornography Detection**: Adult content, sexual language
- ✅ **Violence Detection**: Violent language, terrorism, self-harm keywords
- ✅ **Advertising Detection**: Spam marketing, promotional language

### Action Modes

- `alert`: Log violation, continue processing (default)
- `reject`: Block request, return error
- `allow`: Log only, no blocking

### Customization

- Support custom keyword files (JSON format)
- Support wildcard matching (`敏感*` matches `敏感词`, `敏感内容`)
- 3 threshold levels: low/medium/high
- Per-category enable/disable

### Data Sovereignty

- ✅ All detection in local memory
- ✅ No external HTTP requests
- ✅ No cloud API calls
- ✅ Suitable for intranet/private cloud deployment

## Configuration

```json
{
  "content_safety": {
    "enabled": true,
    "action": "alert",
    "categories": ["politics", "pornography", "violence", "advertising"],
    "custom_keywords": {
      "enabled": false,
      "paths": []
    },
    "log_matches": true,
    "threshold": "medium"
  }
}
```
